# MiraDroid · 开源预览版

MiraDroid（原名“桌面微信扫码”）在 Mac 上操作真实 Android 手机，从手机应用目录打开应用。研究候选新增可选的通用桌面相机：在所选手机 App 内打开相机或扫一扫，以透明框选取电脑桌面，识别与结果始终由原 App 处理。

**本机已更新 build67（源码 `65e1a33`），公开发行仍为 preview.4。通用桌面相机取消每次移动后180ms的反复等待，移动时立即废弃旧区域并继续供图；兼容模式、暂停/刷新、相机/窗口归属及旧帧保护保持。当前小米USB自有板运动对照：每个3秒阶段旧策略0次送图ACK，新策略微信16/19、支付宝17/17次，之后两App均严格识码并清理；ACK数不是屏幕FPS或物理拖动延迟。67无运动双App回归也通过，测试点击→结果帧约1.96/3.64秒，安装后支付宝约3.12秒，不能称整体已稳定提速。原生菜单导航已修正，已有录屏权限在更新后保持有效，64/61/41回退保留。第三App、完整前台/物理拖动及视频同等效果尚未验收。详见[真实运动与扫码验证](docs/DEVELOPMENT.md#build67-通用模式运动供图2026-10-30)。**

新增交互：在微信或支付宝自己的扫一扫中，自动切换到 Mac 独立透明扫码框；桌面直接透过窗口显示，不依赖手机视频回传。拖动停稳后在本机判断二维码是否存在，仅将包含二维码的当前区域原图送给真实手机应用，发送确认后返回完整手机画面显示识别过程和结果。原生手机按钮不被裁切或重绘；Mac 不读取、记录或打开二维码内容。

## 现在能做什么

- 原生 macOS 手机窗口，显示真实 Android 屏幕，鼠标按下、移动、松开实时传给手机。
- USB 设备选择；无线调试的配对码与连接地址输入。内置 ADB 的无线连接已在 App 界面实测；微信独立显示和镜像已通过小米真机后端集成测试。
- 连接后默认请求手机的原生副屏桌面。已在当前小米上确认副屏 HOME 仅返回白屏；遇到该行为时，主窗口显示来自手机实际应用目录的选择器，搜索后点“打开”即在主窗口使用该应用的真实画面。应用列表也可拖出独立窗口，原生拖放仍待 GUI 验收。
- 兼容模式：在手机应用内自行进入扫一扫，精确匹配微信、支付宝扫码页面与相机归属后自动接入桌面；此前 build 40 三轮双应用自动接入、测试码识别及恢复清理通过；build 41 的独立透明框已有双应用主流程通过，物理拖动仍待验收。其他应用不会仅凭“正在使用相机”而自动接入。
- 通用模式候选：连接时明确选择桌面相机，再从应用列表打开任意可启动 App；其相机归属明确且只有一个匹配窗口时接入。扫码、拍照或视频都会使用所选桌面来源，不能仅凭相机事件区分用途。App 可拒绝虚拟显示或虚拟相机，仍需逐个验证兼容性。
- 窗口展开使用本地过渡；黄色按钮或 ⌘M 调用 macOS 原生最小化，跟随系统“神奇效果/缩放效果”和“减少动态效果”设置。
- 可选“手机锁屏时继续使用独立应用”：已在小米 Android 16 无线实测锁屏下的设置/微信画面与滑动响应；手机主屏继续锁定。
- 断开前恢复应用任务并清理本应用的临时显示/相机；失败时保留恢复记录。

## 使用

新构建的应用名与安装包名为 MiraDroid。现有安装的旧名称暂不改动；应用标识、签名身份、本地偏好与恢复记录路径继续沿用，GitHub 仓库地址保持兼容。

1. 将 App 移入“应用程序”后打开。需要 Apple Silicon、macOS 14.4+；手机目标 Android 16，无需 Root。
2. 点连接，选 USB 设备，或在连接窗口完成无线配对。研究候选中勾选“桌面相机（通用）”后，本次所选应用窗口的相机将使用框选桌面，包括扫码、拍照和视频；首次默认关闭，此后记住明确选择。ADB 已随包提供，用户不需要终端。
3. 连接后看手机桌面；若小米副屏桌面显示白屏，主窗口会改用“手机应用”列表。搜索并打开要用的应用，也可从列表拖出独立窗口。需要锁屏使用独立应用时，在连接窗口勾选原有的“手机锁屏时继续使用独立应用”（首次默认关闭，此后记住选择）；这不会解锁手机主屏。
4. 在所选应用里自行点击相机或扫一扫。通用模式按所选窗口及真实相机归属接入，不依赖 App 的扫码页面类名；归属不明或同包多窗口歧义时不送图。首次使用桌面来源需授予此 Mac App 屏幕录制权限。
5. 通用模式会在真实 App 窗口旁显示透明取景框。拖动顶部工具条框选桌面，停稳后持续供图，结果在原 App 内显示；可暂停、刷新或返回。未勾选通用模式时沿用微信/支付宝兼容流程：本机仅检测 QR 是否存在，送图后返回真实应用。后续登录、授权和支付由你决定。
6. 关闭独立窗口会把任务移回手机。收进程序坞会暂停桌面相机，恢复窗口后可继续；退出前等待清理完成。

无线配对端口与连接端口通常不同，请分别填写手机对应页面显示的值。App 会记住上次明确选择的无线设备，打开连接窗口时使用 macOS Bonjour 查找它当前的端口并尝试重连；无需重复输入配对码。发现失败时保留已存地址和手动入口。内置 ADB 本身不承担 Bonjour 发现。新建无线连接由 App 自己管理本地服务，退出时清理；现有 USB 服务继续保留。已配对信任由 Android/ADB 保存，断开 App 不等于撤销信任；可在手机无线调试的“已配对设备”中忘记此 Mac。

## 验证与限制

- 前版锁屏后端真机测试通过：主屏始终锁定，设置独立窗口滑动后中央画面变化，微信独立窗口返回真实帧；停止/重新创建直连编码流、任务恢复与自有资源清理均通过。此结果不代表任意机型、长时间稳定性或参考视频级流畅度已验证。

- 已在小米 Android 16 分别通过 USB 与 Wi-Fi 实测：读取应用目录、设置独立显示、微信独立显示与 H.264 回传、任务恢复与资源清理。无线测试明确使用网络端点，不回退到 USB；主屏与预热微信显示同时镜像、微信新帧返回及恢复清理也已验证。
- 前版已验证 App 无线选择和主屏镜像，用户截图也显示独立微信窗口已打开。本版修复拖出事件被误拦、动画窗口可能保持透明和拒绝打开时无反馈；合成测试通过，已用生产连接服务实测记住旧地址后二次连接并清理；本次已在 App 界面自动找回已记住的无线手机并选中连接，真实镜像帧持续返回；原生拖放仍需 GUI 实测，重启后端口变化的 Bonjour 自动找回已由生产逻辑实测通过。App 内配对码界面和整套扫码过渡尚未完成验收。
- 默认构建和发行使用项目持续保留的自签身份，打包校验证书身份，避免误用旧 ad-hoc 包；不修改系统信任或授权数据库。两个合成构建的身份连续性及异证书拒绝已验证，同一证书连续更新至已安装的 build 67 后，本机实际录屏权限仍为 true，未重新修改 TCC；安装包内两款手机应用原生识码已通过。这不是新 Mac 或其他证书迁移的保证。
- 拖出入口是本 App 的“手机应用”列表；尚不支持直接抓取手机桌面镜像里的任意图标拖出。
- 独立窗口复用同一包的已有窗口；应用可能拒绝虚拟显示或保留手机显示，依机型和应用而异。当前小米的副屏 HOME 白屏不是可用桌面，以真实手机应用目录作为这部手机的入口，不能把目录称为 Android 原生桌面。
- 手机窗口显示原 App 的完整镜像，按钮、识别和结果由手机 App 绘制；透明取景框是单独的 Mac 窗口。通用模式只绑定从本 App 的应用列表打开的、声明相机权限的主用户应用窗口；系统代理拍照、其他包接管相机、同包多窗口或拒绝虚拟设备的 App 可能不可用。兼容模式仍只自动接入微信 `BaseScanUI`、支付宝 `MainCaptureActivity`。通用模式已通过微信/支付宝本轮真机扫码；系统相机尚未观察到虚拟相机流，没有成功的第三款 App 供图结果，不保证所有扫码应用。
- 蓝色移动条/棋盘仅用于显式开发诊断，不在普通菜单显示。历史 build 32 的完整微信测试两轮均识别测试明文并清理，但无线送帧分别约 17.4 / 26.9 fps，请求耗时 p95 约 181 / 33 ms，仍存在明显波动；这些数值不等于物理鼠标拖动延迟或参考视频级流畅度验收。
- 后台合成图的串行/流水线对比已完成测试明文识别和清理；串行约 27.66 / 27.71 fps，流水线约 27.05 / 26.83 fps，未见提速，产品继续使用串行路径。流水线仅保留为测试实验。build 40 只在实时扫码期间声明用户活动，暂停、离开、断开或退出即释放；两轮未采样测试送帧提高，但不能仅凭前后对比把全部卡顿归因于 App Nap，偶发长间隔仍未定位。
- 首次调试授权及每次手机重启后，需要在手机上正常解锁一次。独立锁屏模式仅对本次临时应用窗口生效，要求 ROM 支持并已授予 shell 相应系统权限；不支持时明确失败，不改变手机主屏密码、锁态或锁屏时间。锁屏时仍可保留已授权的独立应用画面，物理主屏仍为锁屏；音频、剪贴板和电脑键盘输入尚未实现。
- 仅 arm64，持续自签身份、未获 Apple Developer ID 签名或公证；旧 ad-hoc 版本迁移仍需要一次录屏授权。本机连续同证书更新已保留实际授权；新机器安装和其他签名迁移尚未验证，不应反复清空系统权限记录。
